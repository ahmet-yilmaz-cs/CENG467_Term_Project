## Project Overview

This project implements an Advanced Retrieval-Augmented Generation (RAG) pipeline with Hard Negative Mining on the HotpotQA dataset. The system trains a Dense Passage Retrieval (DPR) model using BM25-mined hard negatives, builds a FAISS vector index for scalable retrieval, and uses Flan-T5-xl as a generative reader to answer multi-hop questions.

**Pipeline:**
1. Hard Negative Mining (BM25) → `data/hard_negatives_train.json` + `data/hard_negatives_val.json`
2. DPR Fine-tuning with contrastive loss (gradient clipping + LR scheduler + curriculum learning)
3. FAISS vector index over validation corpus
4. Flan-T5-xl generative reader on top-3 retrieved passages
5. Ablation study: BM25 vs vanilla DPR vs hard-negative fine-tuned DPR

## Reproducing Results

### Step 1 — BM25 Baseline
```bash
python src/baseline_bm25.py
# Output: results/bm25_results.json
```

> **Note:** `baseline_bm25.py` evaluates each question against its own 10-passage pool (per-question setting). The metrics in `results/bm25_results.json` therefore differ from the BM25 row in the Results table below, which is produced by `ablation.py` using a shared global corpus.

### Step 2 — Vanilla DPR Baseline
```bash
python src/baseline_dpr.py
# Output: results/dpr_results.json
# Downloads ~800 MB model weights automatically
```

> **Note:** Like `baseline_bm25.py`, this script uses a per-question passage pool. The numbers in `results/dpr_results.json` will not match the "DPR (vanilla)" row in the Results table, which comes from `ablation.py` running over a global FAISS index.

### Step 3 — Hard Negative Mining
```bash
python src/hard_negative_mining.py
# Output: data/hard_negatives_train.json  (80% of mined examples)
#         data/hard_negatives_val.json    (20% of mined examples)
```

Mines hard negatives from the HotpotQA train split and writes an 80/20
train/validation split. The committed run mines 30,000 examples. Output paths
(`data/hard_negatives_train.json` and `data/hard_negatives_val.json`) are read
directly by Step 4.

### Step 4 — DPR Fine-tuning (GPU required)
```bash
python src/train_dpr.py
# Output: models/dpr_hn_v2/epoch1/, epoch2/, epoch3/
```

Training features:
- **Curriculum learning**: 1 → 3 → 5 hard negatives per epoch
- **Gradient clipping**: max_norm=1.0
- **LR scheduler**: linear warmup (10%) + linear decay
- **Per-epoch checkpoints**: each epoch is saved to its own directory; the
  final checkpoint is chosen by **global retrieval** (Step 6), *not* by the
  mini-pool recall during training — that pool (~7 candidates) is near-saturated
  and unreliable for selection.
- Recommended: Google Colab with A100 GPU

To customise hyperparameters, edit the `__main__` block in `src/train_dpr.py`
(fields: `data_path`, `output_dir`, `epochs`, `batch_size`, `lr`).

### Step 5 — Reader Pipeline (GPU recommended)
```bash
python src/reader.py
# Output: results/reader_results.json
```

### Step 6 — Ablation Study (GPU required)
```bash
python src/ablation.py
# Output: results/ablation_results.json
# Retrieval (R@1/3/5/10, MRR@10, nDCG@10) + QA (F1, EM) for all three configs
```

### Step 7 — Reader Comparison (GPU required)
```bash
python src/reader_comparison.py
# Output: results/reader_comparison.json
# Flan-T5-xl vs Qwen2.5-7B vs Phi-4-mini on the fixed DPR+HN retriever
```

### Step 8 — Statistical Analysis
```bash
python src/analysis.py
# Output: results/eval_detail.json  + printed 95% bootstrap CIs,
#         paired-bootstrap significance, strict recall, and a
#         per-category (bridge / comparison / yes-no) breakdown
```

### Step 9 — Reader Fine-tuning (separate experiment, GPU required)
```bash
python src/finetune_reader.py
# LoRA fine-tunes Flan-T5-xl on the TRAIN split, evaluates on val with DPR+HN.
# Reported separately from the zero-shot main ablation (best end-to-end result).
```

This is the authoritative evaluation step. All three configurations (BM25,
vanilla DPR, DPR+HN) are evaluated on the same 500-example validation set
using a single shared FAISS index, producing the metrics reported in the
Results table below.

## Results

All metrics on the HotpotQA validation split (n=500); retrieval is over the
pooled passages of the eval set (multi-hop: ~2 gold passages per question).

**Retrieval quality**

| Config | R@1 | R@3 | R@5 | R@10 | MRR@10 | nDCG@10 |
|---|---|---|---|---|---|---|
| BM25 | 0.704 | 0.862 | 0.904 | 0.980 | 0.793 | 0.692 |
| DPR (vanilla) | 0.714 | 0.854 | 0.888 | 0.932 | 0.793 | 0.688 |
| **DPR + HN** | **0.844** | **0.936** | **0.962** | **0.984** | **0.895** | **0.811** |

**End-to-end QA** (Flan-T5-xl reader on the top-3 retrieved passages)

| Config | F1 | EM |
|---|---|---|
| BM25 | 0.496 | 0.388 |
| DPR (vanilla) | 0.485 | 0.384 |
| **DPR + HN** | **0.583** | **0.466** |

> Reader: Flan-T5-xl (1024-token input budget). A reader comparison on the DPR+HN
> retriever — Flan-T5-xl **0.583** F1 vs Qwen2.5-7B 0.574 vs Phi-4-mini 0.520 —
> showed the 3B encoder-decoder is the strongest, and that the input budget
> (512→1024) was the largest single reader lever (~+0.04 F1 across all configs).

> Rigor (n=500): the DPR+HN gain is statistically significant — ΔF1 +0.097, ΔR@1
> +0.130, **p<0.001** (paired bootstrap). Under the strict multi-hop criterion
> (**both** gold passages in top-5) recall is far lower — DPR+HN 0.616 vs vanilla
> 0.462 vs BM25 0.406. Per-category: bridge questions (F1 0.535) are hardest;
> comparison (0.781) and yes/no (EM 0.909) are handled well.

> Reader fine-tuning (LoRA, train split only) adds only **+0.03 F1 / +0.026 EM**
> (0.583→0.613) — reported separately from the zero-shot main ablation.
> Retrieval, not the reader, is the bottleneck.

Hard-negative fine-tuning improves retrieval R@1 by **+13 points** over vanilla
DPR and sharpens ranking quality (MRR@10 +0.10, nDCG@10 +0.12); the gain is
largest at the top of the ranking, so it propagates end-to-end (**+0.10 F1 /
+0.08 EM**). Notably, vanilla (NQ-pretrained) DPR does *not* beat the lexical
BM25 baseline — the improvement comes entirely from the hard-negative
fine-tuning.
